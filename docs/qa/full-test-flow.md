## 测试范围与临时规则速查

本轮只覆盖一场固定 1v1 战斗：玩家先手，对手为确定性 AI；双方起始 30/30 HP、8/8 能量、10 张固定手牌和 12 张有限牌库。手牌与牌库是独立实例；双方牌库以相同 seed `0x54434101` 独立洗牌，预期得到相同且可复现的顺序。第一轮开局不抽牌；各方以后每次进入自己的回合时先恢复 2 点能量（上限 8）再抽 1 张；牌库空时不抽、不重洗。玩家可以连续行动后结束回合，AI 每回合最多完成一项动作。

固定起手的卡牌定义 ID 为：`c, n, o, cl, b, s, ar, co, no2, h2o2`。牌面 ID 若不展示给玩家，请记录显示名和位置；只在 QA 面板或日志可见时记录 ID/实例 ID。

| 卡牌 | 费用 | 目标 | 本切片动作 |
|---|---:|---|---|
| c | 1 | 自己 | 下次成功反应费用 -1；未用时在自己回合结束过期 |
| n | 1 | 自己 | 下次受到伤害 -1；到对手下一回合结束仍未触发则过期 |
| o | 2 | 对手 | 基础伤害 2 |
| cl | 2 | 对手 | 基础伤害 3 |
| b | 1 | 自己 | 下次成功反应额外尝试抽 1 张；效果跨回合保留至触发 |
| s | 1 | 自己 | 下一次成功伤害 +1；未用时在自己回合结束过期 |
| ar | 2 | 自己 | 立即尝试抽 1 张；牌库为空时无效果 |
| co / no2 / h2o2 / cl2 | 2 | 对手 | 基础伤害依次为 3 / 3 / 4 / 4 |
| co2 / no / n2 / o2 | 2 | 对手 | 基础伤害依次为 3 / 3 / 3 / 2；均为 MT-05 临时输出定义 |

当未被减伤、未额外加成时，伤害按 `max(0, 基础伤害 + 本方本回合首个伤害 +1 + S 加成 - 对方 N 减伤1)` 结算。每方每回合首次成功反应后，产物进入手牌后再额外尝试抽 1 张；这是 fixture 全局修正，不是 C/O 角色被动。B 的抽牌可以与该 fixture 抽牌同时发生。反应基础费用为 2，C 的一次性折扣最多减 1。

反应输入顺序不影响结果。MT-05 配方如下：

| 输入牌 | 候选/产物 | 手工核对点 |
|---|---|---|
| C + O | CO、CO₂ | 两个候选都显示；玩家能分别选择；取消时槽位和状态保留 |
| N + O | NO、NO₂ | 两个候选都显示；玩家能分别选择；取消时槽位和状态保留 |
| Cl + Cl | Cl₂ | 单个产物可解析并进入手牌 |
| C + C | C | 输入是两个不同实例；产物是新实例 |
| N + N | N₂ | 输入是两个不同实例；产物是新实例 |
| O + O | O₂ | 输入是两个不同实例；产物是新实例 |

未列配方（例如 C + N）不支持。失败命令应提供可理解的反馈且不部分改变 HP、能量、牌区、反应槽、效果标记或抽牌状态。HP ≤ 0 或当前手牌数量为 0 都令该方失败；两方在同一原子动作后同时失败则为平局。手牌不包括牌库或弃牌堆。卡牌效果、反应产物和触发抽牌全部结算后再检查终局。

## 测试环境与准备

### 测试者环境

- Windows PC；记录系统版本/构建号、CPU、GPU 与驱动、内存、显示分辨率和缩放比例。
- 实际测试使用键盘和鼠标。手柄可用于补充观察，但不是通过条件；本切片不测试触控。
- 可截图或录屏的工具，以及用于保存证据的本地目录。
- 不需要登录 Steam/Epic 或连接商店服务；发行目标不代表商店 SDK 或在线服务已接入。

### 收到构建后（EXT-BOOT-01）

1. 将交付包解压到一个干净、可写的目录；不要从 Unity 工程、Godot Editor 或仓库源目录启动。
2. 记录包文件名、构建号/提交号、交付渠道、SHA-256 和解压目录。
3. 冷启动一次，记录启动耗时、是否出现错误窗口、崩溃、缺失素材或安全软件拦截。保留原始错误信息。
4. 确认程序可进入单场战斗；若构建有启动菜单，记录从启动到战斗的导航步骤。
5. 确认初始双方数值、玩家先手和固定起手。默认验收要求记录 seed 和双方洗牌顺序；双方同 seed 序列应相同，重开后同一 fixture 应可复现。若包未提供可核验的 seed/顺序日志，将这项数据验收标为 BLOCKED，不猜测；仍可继续其余战斗用例。
6. 记录实际键位和屏幕焦点状态。当前构建使用 Tab/Shift+Tab 移动控件焦点，方向键操作获得焦点的选择控件，Enter/Space 激活焦点控件；选中卡牌后也可按 Enter/Space 使用。R 尝试解析反应，C 清空反应槽，E 结束回合，Escape 打开暂停菜单。多产物反应会显示候选按钮，须再用鼠标点击或键盘焦点确认具体产物；C 可退回槽牌。若构建中键位或行为不同，以实际观察为准并记录差异。
7. 截取战斗初始画面，包含双方 HP/能量、手牌、反应槽和回合标记。

## 输入路径检查

按实际 UI 对下列关键操作逐项记录一种完整可用路径。路径可以使用键盘、鼠标或二者组合；不要要求同一操作必须有键盘和鼠标两套独立入口，也不要以“必须全程纯键盘”判定失败。

| 用例 ID | 关键操作 | 记录实际路径 | 检查 |
|---|---|---|---|
| EXT-INPUT-01 | 检查卡牌详情 | 点击卡牌，或用 Tab/Shift+Tab 聚焦卡牌 | 显示名称、费用、效果和目标方式；不显示 Damage/Buff/Solvent 内部分类 |
| EXT-INPUT-02 | 选择并使用卡牌 | 点击手牌再点击“对自己使用/对手为目标”，或聚焦手牌后按 Enter，再按 Enter/Space 使用 | 目标对象正确；费用与牌区变化正确；当前 fixture 的目标由卡牌规则决定 |
| EXT-INPUT-03 | 将两张元素牌放入两个反应槽 | 先选择手牌，再点击空槽；或 Tab 聚焦卡牌、Enter 选择、Tab 到槽位并 Enter | 每槽最多一张；同一实例不能占两个槽；拖放只是快捷方式 |
| EXT-INPUT-04 | 查看候选并确认产品 | 候选列表可见；用焦点确认或鼠标点击选择 | 仅生成选中的产品 |
| EXT-INPUT-05 | 不确认产物并退出反应流程 | 不选候选；按 C 或使用清槽按钮 | 候选选择前不扣费、不抽牌、不弃牌、不生成产物；清槽后输入牌退回手牌 |
| EXT-INPUT-06 | 清空反应槽 | C 或点击 Clear | 两牌按原位置顺序回到手牌；无费用变化 |
| EXT-INPUT-07 | 结束回合 | E 或点击 End Turn | 槽牌按原位置顺序退回，之后才进入对手回合 |
| EXT-INPUT-08 | 返回、关闭确认框、查看结果及重开 | 按构建显示的焦点/快捷键或鼠标控件 | 不丢失可恢复的选择；终局后只有查看、日志和重开等允许操作仍可用 |

至少确认一个关键流程不依赖拖放。可用鼠标点击卡牌和按钮，也可用键盘焦点选择控件并确认；两种路径不要求为每个操作重复执行。若某项只有拖卡到区域才能完成，记录 FAIL，并附录屏。

## 完整战斗执行步骤

### A. 默认战斗冒烟（EXT-FLOW-01）

1. 从干净解压目录启动并进入默认战斗。
2. 确认画面是一名玩家对一名 AI 对手；没有角色选择、冒险流程或触控 UI。
3. 确认双方各 30 HP、8/8 能量、玩家先手；玩家手牌为 10 张固定起手；牌库/弃牌等区域可读时记录数量。确认元素牌和物质牌可区分，但卡牌详情不显示内部类型名称。
4. 逐项完成“输入路径检查”中的关键操作路径并记录实际设备组合。
5. 任选一张合法伤害牌，确认正确目标受到伤害、费用扣除、被打出的实例进入弃牌区、手牌数量变化和日志一致。首次伤害应包含本方本回合的 +1 fixture 修正；例如 O 的基础伤害 2，若本回合首个伤害动作且没有减伤，预期实际伤害 3。
6. 结束玩家回合。确认 AI 自动完成至多一项合法动作并结束；AI 不应在同一回合继续连打。记录 AI 的手牌、动作、双方状态和日志。
7. 玩家下一回合开始时，确认先恢复 2 点能量、上限 8，再从牌库抽 1 张；首次开局不额外抽牌。重复至少一个完整玩家/AI 轮次。每次对比变化前后的状态并保存记录。
8. 继续使用合法动作打完整场，直到出现玩家胜利或失败。记录每个回合动作、费用、伤害/抽牌、效果标记和最终结果。若发现无法结束、AI 连续行动、双方状态不更新或软锁，立即录屏并登记，不要仅靠重启掩盖问题。
9. 终局后尝试查看卡牌/日志并确认结果可读；尝试一次常规出牌、反应和结束回合，确认它们不会改变终局状态。记录重开按钮/命令的可见名称和设备路径。

### B. 反应、失败回滚与牌区

建议从新的默认战斗开始，在首次结束回合前完成开局手牌能覆盖的测试；如需要第二个相同定义的元素实例，请使用后续抽牌或交付的 QA fixture。两个同 ID 实例也必须是不同实例，不能把一张牌重复放入两个槽。

1. **EXT-REACT-01 — C + O 候选及取消：** 放入两张牌并查看 CO/CO₂。先取消/关闭候选选择；确认两输入仍在槽内，能量、手牌/弃牌、产物和抽牌均未变化。之后选择 CO 完成一次，再从新的/可复现 fixture 选择 CO₂ 完成一次。交换输入槽位重测并核对候选集合相同。
2. **EXT-REACT-02 — N + O 候选：** 按同样方式核对 NO/NO₂，包含取消、分别确认两个产物以及交换输入顺序。多个候选不得在未确认时自动生成默认产物。
3. **EXT-REACT-03 — 单产物配方：** 分别核对 Cl + Cl → Cl₂、C + C → C、N + N → N₂、O + O → O₂。对每组交换槽位并确认相同产物。C+C/N+N/O+O 的输入必须为两个不同实例；产物是新实例。
4. **EXT-REACT-04 — 不支持配方：** 用 C + N 查看/尝试 Resolve。应显示“不支持此配方”或等价反馈，槽牌保留且可清空/换牌；不得扣能量、抽牌、清槽或生成产物。
5. **EXT-REACT-05 — 槽位退回：** 放入一张或两张有效元素牌后执行 Clear；确认牌按原手牌顺序退回、无费用变化。再放入牌并结束回合；未完成的槽牌应按原位置顺序退回手牌。
6. **EXT-REACT-06 — 无效目标：** 尝试把自用牌用于对手，或把伤害牌用于自己。构建可拒绝或阻止非法目标，但必须有可理解反馈；核对 HP、能量、实例区域、效果标记与抽牌状态没有变化。可用拖放尝试非法目标，但不能把拖放作为唯一的合法操作路径。
7. **EXT-REACT-07 — 能量不足/无效动作：** 仅使用构建提供的 QA 状态入口将能量降至费用以下，或交付的自动化日志/fixture 复现。提交动作后确认完全无副作用。外部 UI 没有可安全设置状态的入口时，不手改存档；将此项记为 BLOCKED 并请开发提供 QA fixture。

### C. 效果与回合边界

以下最好使用可复现 fixture；否则记录实际状态，避免 AI 行为或抽牌变化干扰结果。

1. **EXT-EFFECT-01 — C 折扣：** 打出 C 后检查效果提示。下一次有效反应基础费用 2，应减为 1；成功后折扣消费。尝试一次失败/取消的反应，确认折扣仍在且未扣费；若本方回合结束前未成功反应，确认折扣到回合末过期。
2. **EXT-EFFECT-02 — N 减伤：** 打出 N 给自己施加一次性减伤。对手下一次成功伤害应减少 1，最低为 0；触发后标记移除。若对手下次回合结束仍未造成伤害，标记应按 MT-04 过期。保留受击前后 HP 和日志证据。
3. **EXT-EFFECT-03 — B 待抽：** 打出 B 后跨过回合，之后完成一次成功反应。确认 B 额外尝试抽 1 张并消费标记；若同一方本回合首次反应，也应与 fixture 首反应抽牌分开核对。抽牌堆为空时两项抽牌都不应凭空生成牌。
4. **EXT-EFFECT-04 — S 伤害加成：** 打出 S 后进行下一次成功伤害。没有其他效果时应在基础伤害上再加 1；该次后消费。若在回合结束前未触发，应到本方回合末过期。
5. **EXT-EFFECT-05 — Ar 立即抽牌：** 打出 Ar 后确认立即尝试抽 1 张，费用和牌区变化正确；牌库为空时应为 no-op，不应制造副本。
6. **EXT-EFFECT-06 — Fixture 修正：** 核对每方各自每回合的首个成功伤害 +1、首次成功反应额外抽 1。首伤和首反应标记应按各自一方、每回合分别重置；UI 不得称其为 O/C 角色被动。

### D. MT-07 终局分支（需要 QA fixture 入口）

下列初始状态只用于外部测试构建，不是玩家规则设置。开发提供的 fixture 工具可以使用不同名称，但应记录实际 fixture ID、全量初始状态和 seed。状态加载后先截取初始状态，再执行指定的一次动作。若工具不能设置所需的手牌、牌库、阶段或状态标记，相关用例标 BLOCKED。

| 用例 | 初始 QA 状态 | 动作 | 预期结果 |
|---|---|---|---|
| EXT-OUT-01 玩家以 HP 获胜 | 玩家 HP 30，手牌 O+C，能量 8；AI HP 3、手牌至少 1；玩家阶段；双方状态标记清空，玩家首伤未触发 | 玩家对 AI 打出 O | O 伤害 2 + 首伤 fixture 1，AI HP 到 0；玩家手牌仍有 C，结果为 player_won |
| EXT-OUT-02 玩家以 HP 失败 | 玩家 HP 3、手牌至少 1；AI HP 30、手牌 O+B、能量足够；AI 阶段；AI 首伤未触发，玩家无 N 减伤 | AI 执行唯一首个合法伤害动作 O | AI 造成 3 点伤害；AI 仍有 B，玩家结果为 player_lost |
| EXT-OUT-03 玩家以空手获胜 | 玩家手牌至少 1；AI 仅有 Ar，AI 牌库为空、能量至少 2；AI 阶段 | AI 对自己打出 Ar | Ar 抽牌 no-op，AI 手牌变为 0，结果为 player_won |
| EXT-OUT-04 玩家以空手失败 | 玩家仅有 Ar、牌库为空、能量至少 2；AI 手牌至少 1；玩家阶段 | 玩家对自己打出 Ar | 抽牌 no-op，玩家手牌变为 0，结果为 player_lost |
| EXT-OUT-05 平局 | 玩家仅有 H₂O₂、能量 8；AI HP 1 且至少有一张手牌；玩家阶段、首伤未触发、无减伤 | 玩家对 AI 打出 H₂O₂ | 伤害令 AI HP 归 0，打牌令玩家手牌归 0；同一原子动作结算后结果为 draw |

每个终局分支至少运行一次；关键发现修复后按原 fixture 复测。各分支确认结果只设置一次；终局后出牌、放槽、清槽、Resolve、AI 动作和回合推进都不再改变状态；检查卡牌、查看日志、重开仍可用。

### E. 重开与重复性

1. **EXT-RESTART-01 — 重开：** 从胜利、失败或平局结果页各选择一次重开路径（至少覆盖一种终局；若不同结果页各自有确认流程，则逐个覆盖）。
2. **EXT-RESTART-02 — 状态重置：** 重开后确认新战斗回到双方 30 HP、8/8 能量、固定起手与玩家先手；反应槽、临时效果、弃牌区、战斗日志和结果状态均重置。重开不恢复上一局战斗状态；本切片不要求保存进度或中途续战。
3. **EXT-RESTART-03 — seed 可复现：** 核对 seed 为 0x54434101、双方使用独立牌库但得到相同洗牌顺序；相同 fixture 重开后也应复现该顺序。若构建未提供可核验的 seed/顺序日志，将此项标 BLOCKED，不以不可观察作为通过。
4. **EXT-RESTART-04 — 重复输入：** 快速重复点击/按键一次确认按钮，观察是否重复扣费、重复出牌、重复生成产物或跳过多个阶段。出现重复动作时立即录屏并记录按键次数和间隔。

## 性能与稳定性补充记录（EXT-PERF-01）

性能预算是暂定目标：60 FPS、16.6 ms 帧时间、最多 1,000 个 2D draw calls、2 GB 运行内存。请优先使用开发团队提供的已标注工具/overlay 或性能构建；普通发行包若不显示这些指标，不要估算或声称达标，记录“外部构建不可测”并请求相应构建。

有测量工具时，记录设备、分辨率、窗口模式、构建模式、测量工具/版本、测量时长、帧率/帧时间分布、Godot 2D draw 指标的具体名称和数值、进程运行内存。记录峰值和稳定区间；不得把“2D draw calls”与未经确认的其他 draw-call 统计口径混为一谈。完成三场连续战斗/重开时留意崩溃、卡死、明显资源增长和日志错误。
