# TCA 2D Art Bible

> **版本：** 0.1  
> **状态：** Draft；以 Draft 状态的 game-concept.md 和现有资产为依据，视觉锚点与推导支柱仍待独立设计审查。原创首批 PNG 与矢量 UI 已放入 Godot 专用目录，生成来源见 [asset-provenance.md](../../production/art/asset-provenance.md)。  
> **目标：** 给角色、卡牌、战斗 HUD、背景与特效建立可共同执行的视觉规则。  
> **范围：** Godot 4.6.2、GDScript、PC（Steam / Epic）、1280×720 起步视口；适配 16:9 桌面窗口。

## 1. 视觉身份

### 提议的视觉锚点

**每张牌像一份清晰可读的元素档案，每名角色把元素的化学行为变成可辨认的性格；两张牌合成时，信息先被看懂，化学反应再被看见。**

此锚点把游戏概念中的“化学事实进入规则、手牌与能量产生取舍、角色身份改变牌序”转成视觉判断。它暂时不锁定冒险世界的地理、阵营或剧情美术，因为概念稿明确将这些留待后续设计。

### 支持原则与设计测试

1. **信息优先于装饰。** 牌面上的元素符号、物质名、费用、目标和效果不能被光效、插画或边框压住。若缩小到实际手牌尺寸仍读不清，先删装饰。
2. **角色靠轮廓与化学特征辨认。** 颜色只能加强辨识；轮廓、姿势、衣饰结构和化学意象至少还要提供两种线索。灰阶缩略图仍应能分辨主要角色。
3. **反应效果展示过程，不替玩法作决定。** 演出可以连接两张牌、显示反应环或产物空间；配方、产物和结果文字必须来自游戏数据，不能靠贴图文字或视觉暗示制造未定义的规则。
4. **界面像档案，战场像传说。** 卡牌与 HUD 以秩序、留白和稳定边缘承载信息；战场背景和角色光影负责情绪。双方通过相同的深蓝、雾青和暖金色相连，不把所有界面也做成写实场景。

## 2. 情绪与气氛

| 游戏状态 | 情绪目标 | 光色与对比 | 画面职责 |
|---|---|---|---|
| 主菜单 / 进入战斗 | 安静、可信、带一点发现未知的期待 | 暖白纸面、低饱和蓝灰，柔和侧光 | 为开始战斗和当前选择留出明确焦点；菜单场景仍待 UX 设计。 |
| 卡牌查看与选牌 | 专注、可比较、可预测 | 中性暖白底，边缘有稳定的深色焦点线 | 卡片放大或聚焦时只提升轮廓与文字清晰度，不用持续发光干扰手牌。 |
| 常规战斗 | 有压力，但仍能从容规划牌序 | 冷蓝雾气为主、远景带暖色日光；前中景明度分层 | 背景降低局部对比，中心战斗区与卡牌信息比远景更突出。 |
| 反应选择与结算 | 期待、验证、短暂释放 | 两个局部色点向青金色反应环汇合，峰值光效不覆盖文本 | 清楚表达“投入的两张牌 → 反应过程 → 产物选项/结算”，未确认的产物由界面数据决定。 |
| 受到伤害或负面效果 | 立即理解发生了什么 | 伤害使用暖珊瑚色和斜向冲击；控制效果使用对应图形徽记 | 影响聚焦在目标和状态图标，不做全屏红闪、纯颜色覆盖或长时间遮挡。 |
| 胜负结果 | 明确结束当前遭遇 | 深蓝底上用暖白文字与图形符号 | 只表达已由规则判定的胜负；胜负条件组合仍待设计，不预制“全部手牌耗尽”等特定结局插图。 |

当前游戏概念没有定冒险场景、关卡气候或阵营，因此本版本不定义生物群落、城镇、敌人生态和剧情演出。

## 3. 形状语言

### 视觉语法

- **科学信息：** 直线、基线、窄边框、整齐对齐的文本区；化学键用细线和节点表示，公式不依赖装饰字体。
- **卡牌容器：** 竖向矩形为主，边角轻微切角；内部图像使用独立画框。边缘装饰集中在外圈，避免侵入文本安全区。
- **反应空间：** 两个稳定槽位加一条连接轴；产物位置单独出现。圆环只表示反应过程，不默认意味着某个特定化学键或实际分子结构。
- **角色轮廓：** 以披风、肩线、衣摆、发型和随身物件区分；单角色至少要有一个强外形记号和一个次级局部记号。
- **层级：** 可交互物件边缘清楚；装饰退后一个对比层级。战斗区域不得使用与手牌同等清晰度的高频纹理。

## 4. 色彩系统

以下 HEX 是首轮生产色票，需在实际 UI 与角色缩略图上复核。它们以已有战斗背景的蓝紫雾感、卡框暖纸色与角色表的元素色意象为参考；不表示现有素材已获授权。

| 色值 | 色名 | 主要用途 | 约束 |

| #8FB7CC | 雾青 | 次级标记、远景光、次级数值 | 不单独承载敌我或成败含义。 |

## 5. 角色绘制方向

- **表现方式：** 2D 半身或全身角色关键视觉，风格化手绘质感与清晰轮廓并存；人体比例和五官风格在同一批角色中保持一致。战斗场景背景可用柔和绘景，但人物边缘与关键手势要更清楚。
- **化学特征：** 元素特性必须落实到至少一个人物动作、材质或服饰结构上。晶格、玻璃、焰色、钝化膜、管线、雾气等作为具象线索；不能把化学元素只贴成头顶的符号。
- **缩略图检查：** 角色图缩小至 160 像素高时，脸部方向、头发/肩部轮廓和主要识别物仍能区分；在灰阶视图下检查 C/Si、N/Ar 等相近气质角色的剪影差异。
- **画面安全区：** 角色脸部位于图像高度 18%–38%；头饰和手持物件不得越过边缘；底部留出至少 12% 画面用于卡片裁切或 UI 遮挡。
- **化学公式和文字：** 由 Godot UI 按规则数据显示，不烘焙进人物插画或生成背景。模型生成时禁止出现随机字母、配方、徽标和水印。
- **身体、年龄和剧情细节：** 角色设定表未提供的信息不由美术自行锁定。姿势和表情只展示其已写出的战斗定位、性格与外观锚点。

## 6. 战场与环境方向

- 当前只生产单场战斗所需的 2D 战斗画面。可沿用“悬浮岛、雾海、远处遗迹、中央圆形台、暖色天际线”的现有构图作为**内部视觉参考**，但源图需先过授权核查；如未通过，按相同高层次构图重新创作，不临摹具体像素或角色。
- 战斗核心区中央保留低纹理、可读区域；前景地面有明确竞技台形状，远景才使用高频岩石、树影或花草。
- 在 1280×720 视口中心放置牌桌与战斗单位，HUD 文字安全区至少距边缘 5%；背景的重要地平线和中央竞技台需留在中心 80% 宽度内，方便 16:9 窗口裁切。
- 背景与手牌不得使用相同的纸白/细线边框，不要把背景上的高亮圆形误读成可交互槽位。
- 冒险地图、角色家园、不同关卡气候不在当前版本冻结范围内；有新的关卡 GDD 后再扩展环境目录。

## 7. 卡牌与战斗 UI

### 卡牌信息层级

卡牌应当在手牌尺寸下快速传达“是什么、能否打、效果是什么”。推荐从上至下安排：

1. 元素符号或化学式：最大的信息锚点；保持正确大小写、下标和电荷表示。
2. 物质名称与可确认的短描述：紧邻公式，避免与插画抢焦点。
3. 费用与可执行状态：用统一角标和明确数字展示；可用能量不足时同时降亮度和显示状态文字/图标。
4. 效果与目标：可在卡牌放大视图完整阅读，不将内部“伤害 / Buff / 溶剂”开发分类直接显示给玩家。
5. 原子序数、族号、价态等化学资料：只有在数据/GDD 确认后才加入，不从旧图自动推定为必需字段。

旧 CardViewPrefab 可提供 Title、Cost、Art、Meta、Rules 的层级参考；在 Godot 重新搭建 Control 场景，不复用 Unity Prefab 文件。

### 战斗 HUD

- 固定布局分层：战斗状态顶栏、中央战场、角色/目标状态、手牌区、双牌反应槽与产物预览、明确的“确认/清空”行动、日志和结果反馈。
- 颜色、边框和图标共同标识选中目标；按钮需有默认、聚焦、悬停、按下、禁用五种视觉状态。
- 所有关键操作都有键盘/鼠标路径。拖牌提供点击选择、再次点击放入槽位的等价入口；产品选择可用清晰焦点框与确认按钮。手柄是部分支持，焦点顺序仍应可见。
- 不把重要说明只放在 hover tooltip，不把错误信息只用颜色表示；输入帮助文字与图标要能适应键鼠主操作及部分手柄。
- 旧 UI 的主要职责（顶部信息、战场、手牌、反应、日志）保留为信息结构参考；具体面板尺寸和位置按 Godot 的 1280×720/16:9 重建，不照搬 Unity 像素坐标。

## 8. 动画与特效

整体操作由 60 FPS 画面呈现，界面转场一般 0.15–0.35 秒，单次战斗反应约 0.65–0.85 秒；动画不延迟玩家确认和键盘焦点移动。首发动效表见 [first-batch-asset-specs.md](first-batch-asset-specs.md)。

| 动效 | 计划 | 视觉边界 |
|---|---|---|
| 角色待机 | 静态插画上的轻微 0.8 秒呼吸位移；不为每角色先画大量重复帧 | 位移不超过 2 px；不让静态文字随角色一起抖动。 |
| 抽牌 | 8 个关键姿态，0.33 秒，由 UI tween 控制；从牌堆弧形进入手牌并平滑落位 | 卡牌背面/信息方向始终一致；不遮挡当前能量与操作区。 |
| 出牌 | 8 个关键姿态，0.33 秒；抬起、确认、朝目标移动、结算后退出 | 可跳过；不能造成鼠标释放和状态结算错序。 |
| 化学反应 | 8 帧透明特效序列，约 0.67 秒；两张牌向反应轴汇合，环线闭合后出现产物焦点 | 产物公式由数据驱动 UI 绘制；特效不暗示尚未定义的化学结构。 |
| 伤害命中 | 8 帧透明冲击序列，约 0.40 秒；局部冲击、短线粒子、淡出 | 目标周围小范围表现；不用全屏闪白或持续震屏。 |
| 持续状态 | 静态徽记加短暂边框变化，不持续闪烁 | 玩家可以在静止帧读懂状态名称与剩余时长。 |

使用慢进快出或平滑缓动；重要反馈峰值控制在局部，不做频闪。Reduced Motion 设置关闭循环呼吸、屏幕震动和非必要位移，保留状态文字与瞬时图标提示。

### 画布、格式与尺寸

| 类别 | 制作 / 导出规格 | Godot 目标用途 |
|---|---|---|

| 图标 | SVG，viewBox 128×128；可见线条在 32×32 显示时仍清晰；需要时导出 256×256 PNG 预览 | 状态、资源与操作图标；形状和标签同色彩共同表义。 |
| 特效序列 | 4 列×2 行，cell 256×256，透明 PNG，总尺寸 1024×512；每格留至少 4 px 安全间距 | Godot AnimatedTexture/SpriteFrames；切片顺序由规格表固定。 |
| 字体 | 经授权核验的 TTF/OTF；完整保留中文字形和公式字符 | Godot FontFile 与 Theme；不迁移 TMP SDF atlas 或 Unity 材质。 |

- **画布基准：** 16:9，设计基准 1920×1080，运行起步视口 1280×720。重要角色脸、卡牌正文、主要按钮放在画面中心 90% 范围；远景可出血。
- **PNG 色彩：** sRGB；有透明需求时使用 RGBA，边缘在浅/深底上都检查 halo；简单线性 UI 尽量用 SVG 源文件，减少无意义的大型位图。
- **导入：** UI 与卡牌正文关闭 mipmap；插画使用平滑过滤；透明帧集添加 atlas padding 避免相邻格采样渗色。压缩设置以画面质量检查为先，验证后记录实际显存/内存。
- **命名：** 小写 snake_case，角色用元素 ID，例如 char_cl.png；牌图以卡牌数据 ID 命名，例如 h2o2.png；界面用 ui_ 或 btn_ 前缀；特效用 fx_前缀。状态/版本不得塞进文件名，应由目录/资源 ID 区分。
- **目录：** Godot 资源根目录统一使用 `godot_assets/`；角色 `godot_assets/characters/portraits/`；牌图 `godot_assets/cards/illustrations/`；界面 `godot_assets/ui/`；背景 `godot_assets/backgrounds/`；特效 `godot_assets/vfx/`；字体 `godot_assets/fonts/`。Windows 不区分 `assets/` 与 Unity `Assets/` 大小写，因此不能把 Godot 资源放进 Unity `Assets/`。
- **性能预算：** 60 FPS / 16.6 ms、最多 1,000 个 2D draw calls、运行内存 2 GB 是用户确认的暂定原型预算。单屏优先共享图集、避免全屏多层透明粒子；这些是验证目标，不表示当前素材已实测达标。
- **授权流程：** 来源、作者/平台、许可或生成记录任一不明时状态写“待核验”，不得把原图复制进 Godot、提交打包或标成已迁移。引用文件名或查看图片不构成授权。

## 10. 可访问性与输入可读性

- 颜色不单独表达伤害、防护、目标、选中或胜负；同步使用形状、图标、文字和布局。
- 正文目标字号不少于 16 px（1280×720 逻辑视口），关键数值和操作提示不少于 18 px；字号级别变化不能只靠颜色。
- 交互目标建议至少 44×44 px；鼠标操作可点击，键盘焦点有清楚的外描边和顺序，拖放有点击式替代路径。
- 关键状态、错误、费用不足和产物选择都以可见文字或明确定义的图标说明；不要要求玩家通过分辨细微色差才能完成反应。
- 灰阶检查常用状态组合；验证红绿色觉差异下的伤害/腐蚀/能量关系。图标加入截然不同的外轮廓和方向。
- 不使用快速全屏闪烁、连续高频亮暗变化或长时间震屏；提供减少动效选项，且关闭动效后仍保留完整规则信息。
- 字体选择和中文字形须检查简体中文、化学式下标/上标、拉丁元素符号及常用标点；动态文本不烘焙到插画。
- 不能因部分手柄支持而隐藏鼠标/键盘提示；当前确认的关键路径是键盘/鼠标完成。

## 11. 风格边界与审查清单

### 不允许

- 只靠颜色区分角色、敌我、伤害或状态。
- 角色图/卡面/背景内生成随机文字、周期表、品牌标识、化学式或水印。
- 用虚构分子结构代替 GDD 规则中的真实配方和产物。
- 让战斗背景纹理、光效或边框压过卡牌正文和能量状态。
- 未核实授权便复制现有 PNG、字体或从截图抠图；TMP SDF、Unity Prefab、Scene 和 .meta 不作为 Godot 的可运行资源。
- 直接把旧 UI Guide 的 Unity 面板坐标与“Raycast Target”等控件设置当成 Godot UI 实现标准。

### 每批美术验收

1. 灰阶缩略图下角色轮廓与主要 UI 状态可辨。
2. 1280×720 实际手牌尺寸下卡面文字、公式、费用可读。
3. 1920×1080 与 1280×720 两种 16:9 显示下，脸部、反应槽和确认操作不被裁切。
4. 低动效模式下不损失规则反馈；键盘焦点/鼠标悬停都能找到关键动作。
5. 资产来源与授权记录齐全后才允许从“待核验”变为“可迁移”。

## 12. 未决项与后续同步

- 概念稿仍是 Draft；视觉锚点和色票需随独立设计审查调整。
- UI 字号是视觉基线，最终可调尺度和焦点顺序需由 UX 规范确认。
- 完整角色首发数、战斗单位与对手美术尚未由战斗 GDD 确认。
- 反应配方和多产物的化学符号/动画，需要以通过审查的规则表驱动。
- 背景裁切/扩展需要在实际 Godot HUD 占位后确定；现有背景源图授权未核实。
